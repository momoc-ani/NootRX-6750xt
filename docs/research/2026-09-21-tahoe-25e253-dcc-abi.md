# Tahoe 25E253 Displayable DCC ABI 记录

## 适用范围

本文记录 macOS Tahoe 26.4.1 build `25E253` 中 `AMDRadeonX6000` 与 `AMDRadeonX6000Framebuffer` 的 Displayable DCC 调用边界。结论仅用于 RX 6750 XT（`0x73DF/0xC0`）诊断版；更换系统 build 后必须重新核对符号、控制流和结构大小。

本文把反汇编直接证明的内容标为“已确认”，把 Mesa AddrLib 提供但 Apple 二进制未直接证明的字段语义标为“参考”。诊断代码不得因为参考字段名称而改写 Apple 输入或输出。

## `shouldAllocScanoutDcc` 控制流

已确认：

- `arg0`、`arg1` 分别从 `esi`、`edx` 转换为 `float`，写入 request 输入的 `+0x10`、`+0x14`，对应宽和高；
- `arg2` 从 `ecx` 进入，必须非零，并写入输入的 `+0x18`；
- `arg3` 从 `r8d` 进入，先经过资源对象取得的格式转换虚函数，再写入输入的 `+0x04`；
- request 输入为 `0x20` 字节，`+0x00` 的版本值为 `1`；
- request 输出为 `0x10` 字节，`+0x00` 的版本值为 `1`；
- controller request type 为 `0x1A`；
- 返回值只在全局 DCC 位、资源 displayable 位、request 返回码为 0、输出 `capability0` 为 1 时成立。

`arg2`、`arg3` 的业务语义仍采用中性名称 `candidateFlags`、`pixelFormatSelector`；只有经过 Framebuffer 请求结构后的 `+0x04` 才记作 `pixelFormat`。

## AddrLib2 identity

`AMDHWAlignManager2::init` 创建 AddrLib 上下文时，从硬件接口虚表读取三个 32-bit 值：

| 虚表字节偏移 | 诊断名称 | 状态 |
| --- | --- | --- |
| `0x140` | `chipEngine` | 值来源已确认，枚举语义待日志核对 |
| `0x1B8` | `chipFamily` | 值来源已确认，枚举语义待日志核对 |
| `0x1A8` | `chipRevision` | 值来源已确认，枚举语义待日志核对 |

这三个值分别写入 `ADDR_CREATE_INPUT` 的 `+0x04`、`+0x08`、`+0x0C`。诊断 wrapper 只能记录 getter 的返回值，不能替换它们。

## AddrLib2 DCC 结构

`getDccInfo2` 检查两个指针后调用内部 AddrLib 函数，并把 AddrLib 返回码转换为 IOKit 返回码。25E253 使用的输入大小为 `0x34`，输出大小为 `0x48`。

| 偏移 | 大小 | 名称 | 依据 |

| `0x04` | 4 | `dccKeyFlags` | Mesa 字段顺序参考 |
| `0x08` | 4 | `colorFlags` | Mesa 字段顺序参考 |
| `0x0C` | 4 | `resourceType` | Mesa 字段顺序参考 |
| `0x10` | 4 | `swizzleMode` | Mesa 字段顺序参考 |
| `0x14` | 4 | `bpp` | Mesa 字段顺序参考 |
| `0x18` | 4 | `unalignedWidth` | Mesa 字段顺序参考 |
| `0x1C` | 4 | `unalignedHeight` | Mesa 字段顺序参考 |
| `0x20` | 4 | `numSlices` | Mesa 字段顺序参考 |
| `0x24` | 4 | `numFrags` | Mesa 字段顺序参考 |
| `0x28` | 4 | `numMipLevels` | Mesa 字段顺序参考 |

| 偏移 | 大小 | 名称 | 依据 |

## Framebuffer request `0x1A`

`callPlatformFunctionFromDrvr` 在 request `0x1A` 分支中：

- 校验输入、输出指针非空；
- 校验输入和输出的 `version` 均为 `1`；
- 把输入宽高从 float 转换为整数后构造内部 `0x24` 字节请求；
- 调用显示侧 capability 方法；
- 把内部 `+0x14`、`+0x15`、`+0x16` 的三个 bit 写入输出 `+0x04..0x06`；
- 把内部 `+0x18`、`+0x1C` 的两个 32-bit 字段写入输出 `+0x08`、`+0x0C`。

三个 capability byte 与两个 32-bit 返回字段的具体业务语义尚未由符号或控制流证明，因此诊断名称固定为 `capability0..2`、`field0..1`。

## 复查命令

```sh
nm -nm /System/Library/Extensions/AMDRadeonX6000.kext/Contents/MacOS/AMDRadeonX6000 | rg 'shouldAllocScanoutDcc|getDccInfo2|AMDHWAlignManager24init'
objdump -d --no-show-raw-insn --start-address=0x2022e --stop-address=0x2031c /System/Library/Extensions/AMDRadeonX6000.kext/Contents/MacOS/AMDRadeonX6000
objdump -d --no-show-raw-insn --start-address=0x5f4e6 --stop-address=0x5f6c1 /System/Library/Extensions/AMDRadeonX6000.kext/Contents/MacOS/AMDRadeonX6000
objdump -d --no-show-raw-insn --start-address=0x5f87c --stop-address=0x5f8cc /System/Library/Extensions/AMDRadeonX6000.kext/Contents/MacOS/AMDRadeonX6000

```

任何地址、结构大小或版本字段与本文不一致时，诊断代码只允许报告 ABI mismatch，不得读取后续字段或修改 DCC 决策。
